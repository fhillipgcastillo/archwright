# Archwright system layout

This machine was installed by Archwright. It is plain Arch Linux underneath -
pacman, systemd, no vendor layer - with one convention that matters more than
any other, described first.

## The ownership split

Two trees hold configuration, and mixing them up is the mistake to avoid.

| Path | Owner | On update |
|---|---|---|
| `/usr/share/archwright/` | Archwright | replaced wholesale |
| `~/.config/` | the user | never touched |

Archwright seeds a user config file **once**, when it does not exist, and never
again. So:

- To change how this machine behaves, edit the file under `~/.config/`.
- Never edit anything under `/usr/share/archwright/` - the next update
  overwrites it and the change vanishes with no error.
- A user config file that already exists is left alone. If a default seems not
  to have applied, the reason is almost always that the file was already there.

## Where things are

| What | Where |
|---|---|
| Compositor | `~/.config/hypr/hyprland.conf`, shell layer in `hypr/shell.conf` |
| Bar | `~/.config/waybar/config.jsonc`, `style.css` |
| Notifications | `~/.config/mako/config` |
| Launcher | `~/.config/fuzzel/fuzzel.ini` |
| Terminal | `~/.config/foot/foot.ini` |
| Agent settings | `~/.config/archwright/agents.sh` |
| Agent launchers | `~/.local/bin/` |
| Default agent | `~/.local/state/archwright/default-agent` |
| Bootloader | `/boot/limine.conf`, regenerated by `archwright-limine-update` |
| Package lists | `/usr/share/archwright/` |

## The shell layer is one systemd target

The bar, notification daemon, wallpaper, idle daemon and polkit agent all hang
off `archwright-shell.target` as **user** units. To restart the whole desktop
shell without logging out:

```
systemctl --user restart archwright-shell.target
```

Stopping the target stops the whole layer, including the upstream units, which
is done with `PartOf=` drop-ins under `/etc/systemd/user/`. Those drop-ins are
how a package-owned unit is modified here - the unit files themselves are never
edited.

## Snapshots and the bootloader

The root filesystem is btrfs with snapper. `/boot/limine.conf` is generated:
one entry for the running system and one per snapshot, so a bad update can be
undone from the boot menu. It is regenerated by `archwright-limine-update`, and
editing it by hand is pointless - the next regeneration discards the edit.

Never write a `pacman -Syu` that skips the snapshot step.

## The archwright command

```
archwright agent [args]           launch the default agent
archwright default agent <name>   change which agent that is
archwright mise-install <spec>    add a lazy launcher for another CLI
archwright sudo-window [minutes]  passwordless sudo that reverts itself
```

`archwright sudo-window` exists so a long run of privileged commands does not
mean a password prompt every few minutes. It removes itself with a systemd
timer. Ask for the shortest window that does the job, and do not assume one is
open - check for `/etc/sudoers.d/99-archwright-sudo-window`.

## Conventions worth following

- Packages come from the official repositories. Nothing here builds from the
  AUR at install time, deliberately.
- Agent CLIs are lazy stubs in `~/.local/bin/` that call `mise exec`. The first
  invocation downloads; after that it is local. A stub is a plain file the user
  owns - deleting it is how they opt out.
- Configuration lives in text files under `~/.config/`, not in a database and
  not in this file.
